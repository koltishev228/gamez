# Zombie — мультиплеерная зомби-выживалка в духе Project Zomboid

Unity 6 (6000.6.2f1), HDRP, FishNet. Цель — до 200 игроков на сервере, сервер авторитарный.
Язык общения с владельцем проекта — русский.

## Сначала читай доки (папка `Docs/`)

- `GDD.md` — что делаем (механики, роадмап). `Techspec.md` — как (структуры данных, сеть).
- `ComplexMechanics.md` — тяжёлые механики + **раздел 11: 7 инвариантов, карта «где что живёт», чеклист, 5 «никогда не делать»**. Перед любой сетевой/серверной задачей прочитай раздел 11 и раздел, относящийся к задаче.
- `FOV.md` — дизайн тумана войны (полигон видимости → маска → HDRP Custom Pass).
- `Items.csv` — список предметов для генерации ассетов.

Код не должен противоречить докам. Если противоречит — остановись и спроси.

## Ключевые правила (кратко, детали в ComplexMechanics.md §11)

- Сервер — источник правды. Клиент шлёт только намерение, сервер перепроверяет всё.
- Один писатель на ресурс, в серверном методе нет `await`/`Task` (атомарность внутри тика).
- Тяжёлые системы — через `Dirty`-множества и лимит работы за тик, не полный пересчёт.
- События локальных объектов — только подписчикам (Observers), не broadcast всем.
- Единственная точка записи в `TileData` — `SetEdgeState`.
- Зомби — данные (NativeArray + Jobs/Burst), не GameObject/NavMeshAgent.
- Скрытое состояние (заражение и т.п.) никогда не в SyncVar/Reconcile.

## Структура кода

- `Assets/_Game/Simulation/` — игровая логика мира (`World/`: WorldGrid, TileData, EdgeOccluderCache; `Visibility/`: VisibilitySolver, FovSystem, FovDarken.shader).
- `Assets/_Game/Client/`, `Assets/_Game/Net/`, `Assets/_Game/Core/`, `Assets/_Game/Editor/` (редакторские тулзы).
- `Assets/_Game/Client/Legacy/` — старые наброски, не образец для нового кода (есть клиент-авторитарное движение, дубли HealthSystem).

## Текущее состояние: туман войны на паузе

Сам механизм работает (`VisibilitySolver` + `FovSystem` + `FovDarken.shader` + `EntityVisibilitySystem` + `VisibilityTarget`), но **нет надёжного источника стен**: `EdgeOccluderCache` сейчас хранит `_bakedSegments` (Vector2-отрезки) и они пусты, поэтому стены свет не режут. Пробовали и не взлетело:
- рейкаст-бейк `WorldGridBaker` по мешам дома — ломается от Scale/дробной позиции/высоты дома, скатов крыши, отсутствия коллайдеров;
- границы NavMesh — вокселизация даёт «лесенку» из сотен мусорных отрезков;
- автогенерация маркеров по AABB — кривой результат.
Вывод исследования: окклюдеры лучше задавать **данными вручную** (маркеры/тайл-редактор), а не выводить из декоративных мешей. Не переизобретай автобейк без обсуждения.

## Подводные камни проекта

- `ModularHousePack1` без коллайдеров на большинстве стен/дверей/окон. Тул `Tools → Zomboid → Add Missing Colliders To House Modules` добавляет `MeshCollider`.
- Система тайлов считает 1 тайл = 1 юнит по X/Z, «этаж 0» у бейкера около мировой Y=0..3; `VisibilitySolver` пока жёстко читает `floor = 0`. Дом должен стоять на Y=0 и целых X/Z (`Tools → Zomboid → Snap Selected To Grid`).
- `FovSystem`/`VisibilitySolver` активны только в Play (`Application.isPlaying`), иначе глобальный Custom Pass темнит Scene View.
- Рендер — HDRP (FOV-проход написан под HDRP FullScreen Custom Pass).
- Правка `.prefab`/`.unity` руками в YAML рискованна: открывай префаб в Unity и пересохраняй (Ctrl+S). Не меняй Transform корня префаба дома.
- Крупные файлы (`box2.fbx` ~56 МБ) — кандидаты на Git LFS.
- Версионирование раньше было в Unity Version Control (Plastic); `.plastic/` в git не коммитим.
